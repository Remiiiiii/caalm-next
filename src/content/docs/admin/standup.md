A new CAALM org fails when admins invite everyone before deciding how work should flow. Do this sequence.

## The first 10 moves

1. **Sign in as the founding admin** and complete 2FA yourself first.
2. **Confirm org profile** (name, basics) under organization settings.
3. **Decide the role model** — start from default roles; only invent new roles with a written purpose.
4. **Assign permissions explicitly** (especially Super Admin / Org Admin — no mythical implicit powers).
5. **Set division taxonomy** to match how managers actually work.
6. **Turn on required 2FA** if policy demands it *before* mass invites.
7. **Invite a pilot group** (one executive, one manager, one viewer, one content creator if needed).
8. **Load a small set of real records** (or clean sample) and validate dashboards.
9. **Configure notifications** and verify one expiry alert path end-to-end.
10. **Only then** invite the rest of the org + connect Outlook/billing integrations.

## Definition of “stood up”

- Pilot users can each complete their [first week](/docs/learn/first-week) checklist
- At least one contract and one license have owners + dates + files
- Approvals can move without emergency Super Admin intervention
- Audit log shows the pilot activity you expect

## Common standup failures

- Inviting 80 people on day one with wrong divisions
- Giving everyone Super Admin to “save time”
- Connecting Outlook before anyone understands shared calendars
- Skipping a pilot and discovering permission pain in production week two


## Pilot script (two-hour workshop)

Hour 1

- Admin explains mental model (documents, deadlines, ownership, proof)
- Each pilot user signs in + completes 2FA
- Each user opens View My Access and reads it aloud

Hour 2

- Manager uploads/links one real contract and one license
- Reviewer/approver moves one item through the queue
- Executive finds both items on dashboard/analytics
- Content creator publishes a three-paragraph “how we will use CAALM” news post

If any step fails, fix the model before inviting everyone else.

## Exit criteria document (copy/paste)

```
CAALM standup exit criteria
- [ ] Pilot roles verified
- [ ] 2FA required policy decided
- [ ] Division list finalized
- [ ] One contract + one license fully healthy
- [ ] Approval path proven
- [ ] Notification path proven
- [ ] Billing owner named
- [ ] Integration owner named
- [ ] Support contact named for lockouts
```
