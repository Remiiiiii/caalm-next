If you only remember one page from these docs, remember this one.

CAALM is organized around four ideas:

## 1. Documents are evidence

A contract or license without a file is a rumor. CAALM expects records to point at real uploaded evidence in the files library or the record’s own attachment flow.

## 2. Deadlines are first-class data

Expiration dates are not footnotes. They drive dashboard widgets, notification triggers, calendar visibility, and leadership risk views. Bad dates create false calm or false panic — both expensive.

## 3. Ownership beats “someone”

Every critical record needs a person (or clear role) responsible for the next action. Re-assign exists because ownership changes; it is not a niche feature.

## 4. Proof beats memory

Approvals, audit logs, and status history exist so you can answer reviewers without reconstructing Slack archaeology. If it mattered, CAALM should be able to show who did what.

## How screens map to the model

| You want… | Go to… |
|---|---|
| What needs attention now? | Role home dashboard |
| Where is the agreement? | Contracts / Licenses / Files |
| Who decides? | Approvals queues |
| When is it due? | Record date + Calendar + Notifications |
| Are we audit-ready? | Audits + Analytics |
| Can I even do this? | View My Access + Permissions catalog |

## A simple analogy

Think of CAALM like an airport operations board:

- Flights = agreements
- Gates = owners
- Departure times = deadlines
- Manifests = evidence files
- Tower clearances = approvals

Everyone can look at the board. Only the right people can change a gate or clear a flight.
