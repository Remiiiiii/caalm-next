The demo sandbox (`/try`) exists so buyers and new users can feel the product without standing up a full organization first.

## What you get

- Sample contracts, licenses, and dashboard widgets
- Guided tour tips anchored to real navigation
- Ability to click through major workflows without waiting on IT provisioning

## What is different from production

| Topic | Demo | Production |
|---|---|---|
| 2FA | Typically skipped | Required for protected routes when policy/cookies demand it |
| Integrations | Often disabled | Outlook / billing / API keys can be live |
| Data | Disposable sample data | Real org records with audit expectations |
| Users | Sandbox identities | Invited users with DB-backed roles |

## How to evaluate honestly

1. Pick one painful workflow from your real world (e.g., “license renews in 45 days”).
2. Find the equivalent screen in demo.
3. Time how long it takes to answer: owner, date, evidence, next action.
4. Ask whether your roles map cleanly to CAALM’s permission model.

> [!TIP]
> Bring your compliance lead and one department manager to the same demo session. Most “we need custom roles” conversations dissolve once both people see permissions in practice.

When you are ready for real data, start at [Stand up a new organization](/docs/admin/standup).
