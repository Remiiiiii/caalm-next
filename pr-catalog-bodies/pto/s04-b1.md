## Tasks (Who / What / Where / Why / When / How)

### 4.1 get_approval

- **Who:** Users who can view approvals
- **What:** Return one approval request with its current step
- **Where:** wrap approval detail API
- **Why:** Deciding needs the full context
- **When:** Approvals batch
- **How:** Read-only; org-scoped

**Done when**
- get_approval is registered and gated by the approvals view permission; results are scoped to the caller's org

### 4.2 approve_request

- **Who:** Assigned approvers
- **What:** Approve or reject an approval request with a comment
- **Where:** wrap approval decision API
- **Why:** The core approvals action
- **When:** Approvals batch
- **How:** Confirm decision; audit; only the assigned approver or a permitted role

**Done when**
- approve_request is registered in the assistant tool registry and only offered when the user has the approver permission for that step
- Mutating call shows a confirm step and writes an audit entry (who/what/when/tenant) on success; no role-name bypass

### 4.3 reassign_approval

- **Who:** Users who can manage approvals
- **What:** Reassign or escalate an approval step

- **Why:** Reviewers go out of office; routing must move
- **When:** Approvals batch
- **How:** Confirm; audit

**Done when**
- reassign_approval is registered in the assistant tool registry and only offered when the user has the approvals manage permission
- Mutating call shows a confirm step and writes an audit entry (who/what/when/tenant) on success; no role-name bypass

**Done when**
